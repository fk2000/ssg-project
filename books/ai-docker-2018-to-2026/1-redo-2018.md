2018年5月に、「docker-composeのRailsアプリをherokuにデプロイする」という記事を書きました。MySQL を使う Rails アプリを docker-compose（複数のコンテナをまとめて動かす仕組み）で開発し、そのまま Heroku（アプリを置くだけで動かしてくれるクラウドサービス）に載せる手順です。

https://note.com/fk2000/n/na1768ff51441

それから8年がたち、Heroku も Docker も Rails も大きく変わりました。そこでこの章では、2018年の構成を2026年の道具と AI でやり直してみます。この章の範囲は「2018年から何が変わったか」と「手元で起動するまで」です。Heroku は実際には載せず、公式の手順と注意点を要約します。

  - Docker 環境：OrbStack（Mac で Docker を動かすためのアプリ）
  - Docker：29.8.2（Client と Server）
  - Docker Compose：v5.5.0

  - 実施日：2026年10月20日
  - AI ツール：Cursor と Grok Bot

## 結論：2018年の手順は、そのままでは通りません

今のやり方は `docker compose`（ハイフンなし）です。Linux で 2018年風に `docker-compose` と打つと、Compose V1 が入っていなければ「command not found」になります。一方、OrbStack を入れた Mac では `docker-compose` もそのまま動き、中身は新しい Compose（v5.5.0）でした。2018年風の compose ファイルも、先頭の `version:` は「もう使わないので消して」と警告されます。

Heroku に載せる流れ（CLI を入れてログインし、アプリを作り、DB を足して、環境変数を入れ、デプロイ）は、公式の手順を見るかぎり今も同じです。ただ、次の3点が変わりました。

1. **無料では載せられなくなりました。** いちばん安い Eco dyno（dyno は Heroku でアプリが動く入れ物）も月 $5 かかります。
2. **2018年に使った MySQL のアドオン（追加機能）ClearDB は、公式の一覧ページで見つかりません。** 別の MySQL アドオンか、Heroku Postgres を検討することになります。
3. **Docker で載せる方法は公式に2つあります。** ただし公式は「特別な理由がなければ Docker を使わず buildpack（Heroku 標準の自動ビルド）を」と勧めています。さらに、新しい Fir 世代の Heroku では Docker デプロイそのものが使えません。

AI に compose ファイルや Dockerfile（コンテナの作り方を書いたファイル）を書かせると、下書きはすぐ出てきます。それでも、DB につながるか、古い書き方が混ざっていないかは人が確かめる必要がありました。今回も AI はいくつか間違えました。直して起動するまで、全体で約40分でした。

## 2018年から変わったこと

### `docker-compose` は `docker compose` になりました

Docker 公式は、Python で書かれた Compose V1（`docker-compose`）を「保守を終えた」としています。今は Go で書かれた V2（`docker compose`、Docker 本体のサブコマンド）を使います。

https://docs.docker.com/retired/

V1 のサポートは2023年6月末で終わりました。

https://www.docker.com/blog/new-docker-compose-v2-and-v1-deprecation/

ハイフンをスペースに変えるだけで、ほとんどのコマンドはそのまま動きます。ただし、コンテナ名の区切りが `_` から `-` に変わりました。2025年に出た Compose v5 も、同じ `docker compose` コマンドです。

https://docs.docker.com/compose/support-and-feedback/faq/

### Rails は最初から本番用 Dockerfile を作ってくれます

Rails 7.1（2023年10月）からは、`rails new` で本番用の Dockerfile、`.dockerignore`、`bin/docker-entrypoint` が自動で作られます。2018年のように、Dockerfile を一から書く必要はなくなりました。

https://rubyonrails.org/2023/10/5/Rails-7-1-0-has-been-released

ただし、この Dockerfile は「本番用で、開発用ではない」とファイルの中に書かれています。開発用は Dev Containers を使うよう案内されています。Rails 8 からは、デプロイの道具として Kamal も標準で入ります。

https://github.com/rails/rails/blob/main/railties/lib/rails/generators/rails/app/templates/Dockerfile.tt

## つまずきポイントの一覧

手元で動かしたときに出たものです。Heroku 側の注意点は、あとの「Heroku：公式の手順と注意点（要約）」にまとめています。

1. **`docker-compose` コマンドがない。** 今の Docker では `docker compose` を使います。
2. **compose ファイルの `version:` で警告が出る。** Compose V2 は `version` を読まずに無視します。消してかまいません。
3. **`A server is already running` で Rails が起動しない。** 前回の `tmp/pids/server.pid` が残っていると起きます。起動の前に消すようにします。
4. **DB より先に Rails が起動して、つながらない。** `depends_on` だけでは DB の準備ができるまで待ちません。`healthcheck` と `condition: service_healthy` で待たせます。
5. **`~/.docker` の持ち主が root になっていて、ビルドが止まる。** 以前 `sudo` で docker を動かしたことがあると起きます（くわしくは後半の「実際につまずいたところ」）。
6. **AI のファイルを別のフォルダに保存して、`Dockerfile.dev` が見つからない。**
7. **`compose.yaml` と `compose.yml` が両方あって、警告が出る。**

## ここから手を動かします

ここからは、手元で打ったコマンドを順番に載せます。手元で起動するまでが範囲です。

## 手順1：2018年風に打ってみる

次の内容を `docker-compose.2018.yml` という名前で保存します。

```yaml
version: '3'
services:
  db:
    image: mysql:5.7
    environment:
      MYSQL_ROOT_PASSWORD: password
  web:
    build: .
    command: bundle exec rails s -p 3000 -b '0.0.0.0'
    volumes:
      - .:/app
    ports:
      - "3000:3000"
    depends_on:
      - db
```

```
$ docker-compose up
$ docker compose -f docker-compose.2018.yml config
```

### `docker-compose` を打った結果

Mac（OrbStack）では、ハイフン付きのコマンドがまだ動きました。

```
$ docker-compose version
Docker Compose version v5.5.0
$ docker-compose up
no configuration file provided: not found
```

エラーは compose ファイルがないためで、コマンド自体は動いています。作業用の Linux（Compose V1 が入っていない環境）では「command not found」でした。環境によって結果が違うので、記事や手順書では `docker compose` で書くのが安全です。

### `version:` の警告

`docker compose -f docker-compose.2018.yml config` では、Mac でも Linux と同じ警告が出ました。

```
the attribute `version` is obsolete, it will be ignored, please remove it to avoid potential confusion
```

「`version` は無視するので消して」という意味です。

## 手順2：AI と一緒に今のやり方で動かす

### 2-1. Rails アプリを作る

手元に Ruby を入れなくても、Ruby のコンテナの中で `rails new` できます。

```
$ mkdir -p ~/ai-docker-01 && cd ~/ai-docker-01
$ docker run --rm -v "$PWD":/app -w /app ruby:3.4 bash -c "gem install rails --no-document && rails new . --database=mysql --skip-git --skip-bundle"
```

今回は Rails 8.1.4 が入り、`ls` で見ると Dockerfile はできていました。

### ファイルの持ち主を戻す（Linux）

Linux では、コンテナが root で作ったファイルを自分の持ち物に戻すため、`sudo chown -R "$(id -un)":"$(id -gn)" .` を打ちます。`$(id -un)` は自分のユーザー名、`$(id -gn)` は自分のグループ名です。Mac（OrbStack）では、ファイルは最初から自分の持ち物なので、この行は飛ばしてもかまいません。

作られた `Dockerfile` は本番用なので、手元の開発には別に `Dockerfile.dev` を用意します。

### 2-2. AI に compose.yaml と Dockerfile.dev を書かせる

AI に見せたのは 2018年の compose ファイルだけです。それをもとに、今の Compose（V2）の書き方で `compose.yaml` と開発用の `Dockerfile.dev` を書いてもらいました。プロンプト（AI への指示文）と出力のチェックは第2章で詳しく扱います。

#### AI が間違えた4つ（くわしくは第2章）

1. `mysql:8.0` を選んだ
2. `server.pid` を消す処理がなかった
3. まだない `Gemfile.lock` をコピーしようとしてビルドが止まった
4. healthcheck の回数が少なかった

手元で起動まで確かめた形はこうです（AI の出力をどう直したかは第2章）。

```dockerfile
FROM ruby:3.4
RUN apt-get update -qq && apt-get install -y --no-install-recommends default-mysql-client && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY Gemfile Gemfile.lock* ./
RUN bundle install
COPY . .
CMD ["bin/rails", "server", "-b", "0.0.0.0"]
```

```yaml
services:
  db:
    image: mysql:8.4
    environment:
      MYSQL_ROOT_PASSWORD: password
    volumes:
      - db-data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-ppassword"]
      interval: 5s
      retries: 20
  web:
    build:
      context: .
      dockerfile: Dockerfile.dev
    command: bash -c "rm -f tmp/pids/server.pid && bin/rails server -b 0.0.0.0"
    environment:
      DATABASE_URL: mysql2://root:password@db:3306
    ports:
      - "3000:3000"
    volumes:
      - .:/app
    depends_on:
      db:
        condition: service_healthy
volumes:
  db-data:
```

### 2-3. 起動して DB を作る

```
$ docker compose up -d --build
$ docker compose exec web bin/rails db:prepare
$ curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/up
```

#### 起動にかかった時間

`time docker compose up -d --build` の結果は、合計で **2分37秒** でした。内訳はこうです。

- `mysql:8.4` のイメージの取得：11.0秒
- web のイメージのビルド：約120秒（そのうち `bundle install` が 48.4秒）

`docker compose ps` では、db が `Up (healthy)`、web が `Up` になりました。

#### DB を作って応答を確かめる

`db:prepare` では DB が作られ、`/up`（Rails が用意している、動いているかを確かめる URL）は 200 を返しました。

```
$ docker compose exec web bin/rails db:prepare
Created database 'app_development'
$ curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/up
200
```

ログには Rails 8.1.4、Puma 8.0.2（Rails の Web サーバー）、Ruby 3.4.11（aarch64）と出ていました。Linux と同じ組み合わせが Apple Silicon の Mac でも動きました。

### 2-4. エラーが出たら

```
$ docker compose logs web --tail 50
```

### 2-5. 実際につまずいたところ

Mac では、次の3つで止まりました。くわしい中身と直し方は第2章で扱います。

- `~/.docker` の持ち主が root になっていて、ビルドが `permission denied` で止まった。次のコマンドで自分の持ち物に戻せます。

```
$ sudo chown -R "$(id -un)":"$(id -gn)" ~/.docker
```

- AI のファイルを1つ上のフォルダに保存していて、`Dockerfile.dev` が見つからなかった。
- `compose.yaml` と `compose.yml` が両方あって、警告が出た（Compose は `compose.yaml` を使います）。

ログを AI に読ませる方法は、第6章（追加予定）で詳しく書きます。

### 2-6. 片付け

```
$ docker compose down -v --rmi local
```

`-v` で DB のボリューム（データを保存する場所）も消えます。残したいデータがあるときは付けません。Linux では、続けて次を打ってフォルダを消します（Mac では1行目は不要です）。

```
$ sudo chown -R "$(id -un)":"$(id -gn)" ~/ai-docker-01
$ cd ~ && rm -rf ~/ai-docker-01
```

## Heroku：公式の手順と注意点（要約）

この本では Heroku に実際には載せていません。以下は公式ドキュメントの要約です。

- **無料プランは2022年11月28日に終わりました。** 今は Eco dyno が月 $5（30分アクセスがないと眠る）、常に起きている Basic が月 $7 です。DB のアドオンも別料金です。

https://devcenter.heroku.com/changelog-items/2502

https://www.heroku.com/pricing/

- **Docker で載せる方法は2つです。** Container Registry（手元で作ったイメージを送る：`heroku container:push web` → `heroku container:release web`）と、heroku.yml（Heroku 側でイメージを作る：`git push heroku main`）です。ただし公式は、特別な理由がなければ buildpack（Heroku 標準の自動ビルド）を勧めています。

https://devcenter.heroku.com/articles/container-registry-and-runtime

- **世代に注意します。** 新しい Fir 世代では Docker でのデプロイが使えず、Cedar 世代のアプリだけが対象です。

https://devcenter.heroku.com/articles/generations

- **コンテナの決まりがあります。** 待ち受けるポートは `$PORT` で渡され（`EXPOSE` は使われません）、コンテナは root 権限では動きません。
- **MySQL のアドオン ClearDB** は、2026年10月20日の時点で Heroku Elements の一覧ページが見つかりません（404）。JawsDB MySQL などのアドオンか、Heroku Postgres が候補です。

https://elements.heroku.com/addons/jawsdb

## この章のまとめ

- `docker-compose` は `docker compose` に替え、compose ファイルの `version:` は消します。
- Rails 7.1 以降は、本番用の Dockerfile が最初から作られます。手元の開発用には `Dockerfile.dev` を別に用意します。
- 手元では `docker compose`、`version:` なし、DB の準備を待つ、`server.pid` を消す、の4点で 2018年の構成が動きます。Apple Silicon の Mac（OrbStack）でも、起動まで2分37秒、全体で約40分でした。
- AI は下書きが速い一方で、古い書き方や終わったサービスを出すことがあります。一次ソースと経験で確かめましょう。

## おわりに：経験は AI 時代も武器になります

AI はところどころ間違えましたが、どれもすぐに直せました。すでに経験したことのある内容だったからです。AI に下書きを任せ、経験で確かめる。この組み合わせなら、速く変わる技術にもついていけます。
