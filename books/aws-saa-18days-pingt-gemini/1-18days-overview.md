AWS Certified Solutions Architect – Associate（ソリューションアーキテクト アソシエイト。以下 SAA、試験コード SAA-C03）に、学習開始から18日で1回受験して合格しました。インフラエンジニアとして前職で AWS を触っていた経験を土台に、短期で合格ラインまで持っていくために使った道具と進め方の「地図」を、この本にまとめています。

この第1章は無料です。ここでは「何を、どの順で、どの道具に任せたか」までを見渡します。Ping-t の周回のしかたや Gemini への具体的な聞き方は、第2章以降に回します。

## この本が向いている人・向いていない人

向いているのは、次のような方です。

- インフラやクラウドの実務がある程度あり、「用語は知っているが試験の問い方に慣れていない」と感じている方
- 長期間ダラダラ勉強するより、期限を切って集中したい方
- 模擬試験と解説を繰り返し、苦手だけを潰すやり方が好みの方

向いていないのは、次のような方です。

- AWS をほとんど触ったことがなく、サービス名から覚え直す必要がある方（その場合は学習期間が長くなりがちです）
- 「必ず何日で合格できる」といった保証を求める方（個人の結果であり、同じ日数・同じやり方で誰でも同じ結果になるわけではありません）
- 問題文や解説の丸写し・暗記だけで通したい方（この本では公式の考え方を優先し、AI の回答を鵜呑みにしません）

実務経験の有無で読み方が変わります。経験がある方は「再確認と未経験サービスの穴埋め」が主戦場です。経験が薄い方は、第3章で触れる基礎固めの比重を増やし、18日にこだわらずカレンダーを伸ばす前提で読んでください。

## 18日間の学習地図（全体像）

進め方は大きく3段です。細部の日次テンプレや問題セット名の運用は有料章に譲ります。

1. **1〜14日：基礎固め**  
   教科書のレクチャーと演習を並走します。実務で触れていた部分の再確認と、未経験サービスの仕様のインプットが中心です。ここでのゴールは「用語とサービスの役割が頭に浮かぶ」ことであり、まだ試験の満点を狙う段階ではありません。
2. **15〜18日：模擬試験の猛特訓**  
   Ping-t の試験レベル模擬を繰り返し、試験特有の「問い方」に体を慣らします。実務経験があっても、ここを飛ばすと本番で迷いやすいです。本番は機械翻訳調の日本語や、初見の専門用語で戸惑うことがありますが、模擬で型を掴んでおくと耐えやすくなります。
3. **最終仕上げ：苦手の深掘り**  
   模擬で落とした問題や、解説を読んでも腑に落ちない箇所を Gemini に聞き、「なぜその選択肢が誤りか」「実務ではどう使うか」まで潰します。得点率を直前で伸ばしたのは、この「ミスの再消化」でした。

地図としてはこれだけです。前半で穴を埋め、後半で試験の型に寄せ、最後に弱点だけを焼く、という順です。「何周するか」「どのプロンプトで聞くか」「当日のフラグ運用」は、このあとの章で具体に落とします。

試験当日の細かい戦術（見直しフラグの本数や時間切れの回避）も、ここでは触れません。手応えの話だけ先に書いておくと、Ping-t の解説をきちんと理解していれば正答できる問題が大半だった、というのが率直な感想です。

## 使ったツール4種の位置づけ

基本は次の4つです。役割がかぶらないように振り分けました。費用の境界や時間配分の表は第2章で詳しく書きます。

1. **書籍（教科書）**  
   『AWS認定資格試験テキスト AWS認定 ソリューションアーキテクト − アソシエイト教科書 第3版［SAA-C03］対応』  
   体系的な知識の棚卸し用です。辞書のように開き、穴がある章から埋めます。最初から最後まで通読するより、「いま弱い領域」にジャンプする使い方の方が、短期では効きやすかったです。
2. **Ping-t（演習・模擬）**  
   問題を解いて「試験の型」に慣れる主役です。特に終盤の試験レベル模擬が合格直前の手応えづくりになります。ここを本の中心に据えた、と言ってよいです。  
   https://ping-t.com/
3. **AWS Skill Builder（公式）**  
   試験の準備教材と、受験予約（Pearson VUE）への導線です。公式の言い回しや範囲感を確かめる場所、という位置づけです。模擬の手応えが出たら、そのまま予約に進める導線としても便利でした。  
   https://skillbuilder.aws/
4. **Google Gemini（補完）**  
   ミス箇所と「なぜ誤答か」の深掘り用です。丸暗記や公式と矛盾する説明の採用はしません。聞き方の型は第5章に置きます。  
   https://gemini.google.com/

一言でまとめると、教科書で地図を直し、Ping-t で筋肉をつけ、Skill Builder で公式の言葉に触れ、Gemini で傷口だけ縫う、です。公式のドキュメントや Well-Architected（よく設計された枠組み）の考え方と食い違う説明が出たら、公式を優先してください。AI は補助であり、採点基準そのものではありません。

## この本で得られること／得られないこと

**得られること**

- 実務ありエンジニアが、18日で SAA-C03 に届いたときの道具分担と順序の再現しやすい地図
- 教科書・Ping-t・Skill Builder・Gemini の使い分けの考え方
- （有料章）日次の進め方、模擬の周回設計、Gemini への聞き方、試験当日の戦い方の体験ベースのメモ

**得られないこと**

- Ping-t や市販書の問題文・解説の転載
- 「誰でも18日で合格」といった保証
- 未検証のスコアや、他資格の学習時間の創作
- AWS 公式の代わりになる最新のサービス仕様の網羅（仕様は公式の更新を見てください）
